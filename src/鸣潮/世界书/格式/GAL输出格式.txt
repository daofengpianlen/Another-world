GAL输出格式:
  rule:
    - 每次 assistant **剧情回复**必须按顺序输出：<gal>…</gal> → <options>（可选）→ <StatusPlaceHolderImpl/> → **<UpdateVariable>…</UpdateVariable>**
    - **禁止**在 <StatusPlaceHolderImpl/> 处结束回复；StatusPlaceHolderImpl **不是**结尾，其后**必须**紧跟 UpdateVariable
    - **禁止**省略 <UpdateVariable>：凡有剧情推进、对话、亲密互动、时间流逝、好感/穿着/生理/性爱状态变化，一律视为有 stat_data 变化，UpdateVariable **必填**
    - 仅当整段回复为纯 OOC 说明、且确认无任何 stat_data 变化时，才可省略 UpdateVariable（极少见）
    - 没有 <UpdateVariable> 则手机「状态 / 剧情 / 好友 / 信息」**不会更新**；MVU 楼层变量保持上一楼旧值
    完整金标准示例见世界书：
    ·「小爱界面完整输出示例」— 开场双角色 + 完整 UpdateVariable
    ·「日常亲密场景完整输出示例」— 后日谈亲密 + 完整 UpdateVariable
    ·「完整首楼回复示例」— 骨架 replace 版
    - <gal> 内标签按剧情时间顺序排列；除 <gal> 与 <UpdateVariable> 外，不要输出大段无标签纯文本剧情
    - 伪同层界面以 **<gal> 是否存在** 作为「已进入游玩阶段」的判定；仅 <StatusPlaceHolderImpl/> 不算开局完成
    - **禁止** 输出 <choice>、<opt>；玩家通过伪同层底部输入框自由行动，<options> 仅作快捷建议
    - **标签分工（禁止混用）**：
      · **女性角色**（stat_data.女性角色 中已登场或本段出场的女性）→ **只能** `<z>角色名<pic>场景名</pic>台词<心>…</心></z>`，**禁止** `<other>` / `<j>`
      · **{{user}} / 漂泊者 / 玩家本人** → **只能** `<other name="显示名" heart="内心">台词</other>`，**禁止** `<z>`（玩家不是主标签角色，不写 pic）
      · **男性 NPC**（伤痕、忌炎等，见 CG 规范「男性角色」）→ **只能** `<other>`，**禁止** `/女性角色/{名}` 与 `<z>`
      · **次要路人**（店员、无名群众）→ **只能** `<other name="…" heart="…">…</other>`
      · **禁止**同一角色在同一条回复里混用 `<z>` / `<other>` / `<j>`
      · `<z>` 内角色名须与 `/女性角色/{名}` 键名**完全一致**；pic 写 CG 场景名，禁止 catbox/URL
      · **禁止**用单字/短名触发模糊匹配（如写 `<z>空` 不得匹配「夏空」）；角色名须与世界书/CG 库全名一致
    - pic 内写 **CG 场景名**（如 `日常`、`亲吻`、`正常位做爱`），**禁止** 写 catbox 文件名或 https URL
    - **权威白名单**：各角色可用场景名见世界书「[mvu_gal]CG插入规范」；表中没有的场景**禁止**输出 pic
    - pic 与 <z> 角色名组合查表：`<z>秧秧<pic>日常</pic>` → 秧秧·日常 CG（本地 assets）
    - 场景名可简写：`日常` 可匹配 `日常状态` / `日常形态` 等
    - **禁止** `<z>漂泊者` / `<z>{{user}}`；玩家台词用 `<other>`
    - pic **必须成对闭合** `</pic>`，**禁止**写成 `</p>`
    - <心> 内写主角/NPC 内心独白；可省略 `</心>`，但建议写全
    - JSONPatch 路径须与 stat_data 结构一致（见「[mvu_update]变量更新规则」「MVU格式要求」）；**禁止**自创根路径
    - 支持 op：**replace**、**add**、**insert**、**delta**；首登场可用 add/insert 写 /女性角色/{名} 与可选 /contact/{名}
    - **不要** 修改 `_storyState`、`指令` 下字段，除非世界书「剧情指令」条目明确要求
    - 开场脚本提交后，AI 第一条剧情回复**必须**含 <gal>，否则伪同层不会挂载

  标签说明:
    gal: |-
      剧情正文容器。伪同层只渲染此块内内容。
    p: |-
      旁白。第三人称环境、动作、感官描写。
      示例：<p>云陵谷的晨雾尚未散尽，天光从今州城外的山脊间漏下来。</p>
    z: |-
      **女性角色专用**（stat_data.女性角色 中的女性）。{{user}}/漂泊者/男性 NPC/路人 **禁止使用**。
      格式：
      <z>角色名<pic>场景名</pic>台词正文<心>内心独白</心></z>
      · 角色名：与 CG 库及 /女性角色/{名} **全名一致**（禁止单字简称导致误匹配，如「空」≠「夏空」）
      · pic：可选；CG **场景名**，不是文件名
      · 台词与 <心> 之间不要插入 | 等分隔符
      · 省略 pic 时仍须保留 <z>…</z> 结构
    j: |-
      **已废弃**。解析器兼容旧楼层；**新输出禁止**使用。
    other: |-
      **{{user}} / 漂泊者 / 玩家本人 / 男性 NPC / 次要路人** 专用。**女性角色禁止**用本标签。
      格式：<other name="路人名" heart="可选内心">台词</other>
      · name、heart 属性必填（heart 可为空字符串）
      · 玩家发言不写 <pic>；若该 NPC 需持续追踪且为女性 → add /女性角色/{名}，此后其对话改 `<z>`
    options: |-
      行动建议，写在 </gal> 之后；每行一条，须含 HTML 颜色标记供前端解析：
      <options>
      <font color="#38bdf8">🗣️ 向秧秧询问情况</font>
      <font color="#f472b6">👀 观察周围环境</font>
      </options>
    StatusPlaceHolderImpl: |-
      兼容旧 regex 浪潮状态栏占位符；伪同层会 strip，不显示。
      写法：<StatusPlaceHolderImpl/> 或 <StatusPlaceHolderImpl />
    UpdateVariable: |-
      MVU 变量更新块，**每条剧情回复末尾必填**（格式见「[mvu_update]变量输出格式」）。
      写在 <StatusPlaceHolderImpl/> **之后**，不可省略。
      亲密/性爱场景须 replace：女性角色.{名}.性爱状态、生理状态、额外信息.内心想法；好感可用 delta。
      pic 禁止写 i75k8e.mp4 等文件名；须写场景名如 手交、日常、亲吻。
